# Product Reality operator checklist

Use this checklist during the first representative lawful full-song Product Reality session.

- Confirm the packaged Windows build/artifact under test.
- Open the real project through the desktop application.
- Start the Product Reality recorder before normal-path work begins.
- Time launch/open, intake, mapping, shared timing review, arrangement review, validation/export, and package stages as they occur.
- Mark only genuine human review/correction intervals as editing time.
- Record every Bass/Lead/Rhythm correction in the appropriate category.
- Record confusing states, responsiveness problems, and required workarounds immediately rather than from memory afterward.
- Exercise playback synchronization, direct event selection, position/timing/technique edits, chord/fingering review, and undo/redo.
- Note any normal operation that still requires CLI or PowerShell.
- Exercise validation/export/package handoff stages that are currently available through the desktop path.
- Finish with an explicit PASS or FAIL and the reason.
- Review the generated local JSON/Markdown report.
- Create/update focused GitHub issues for evidence-backed problems.
- Perform the milestone Issues-tab sweep and select a bounded set of the highest-value follow-up fixes.

Do not weaken musical/source/tone/package human review gates merely to obtain a passing Product Reality result.
