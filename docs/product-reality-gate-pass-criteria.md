# Product Reality Gate v1 pass criteria

The first Product Reality Gate is intentionally strict about normal-path blockers but does not require the entire long-term product roadmap to be finished.

A v1 session may PASS only when all of the following are true for the tested packaged build and lawful representative project:

- the packaged Windows application launches and opens the project without hidden repair steps;
- recording + complete-score intake and Bass/Lead/Rhythm mapping can be completed through the normal desktop path;
- shared timing review and synchronized playback remain usable during repeated review/edit operations;
- direct arrangement selection and currently implemented accepted position/timing/technique/chord/fingering edits behave correctly;
- undo/redo restores accepted review authority predictably;
- no reproducible wrong output, data loss, hard safety violation, or normal-path blocker is observed;
- no severe responsiveness defect prevents practical full-song review;
- required CLI/PowerShell workarounds are either absent from the normal path being evaluated or explicitly judged outside the currently claimed desktop scope;
- measured correction/workflow evidence is recorded rather than estimated;
- the tester records an explicit reason supporting PASS.

A session must FAIL when a normal-path blocker, reproducible wrong output/data loss, hard safety violation, or severe responsiveness defect is observed.

Lower-severity usability friction does not automatically force failure, but it must be recorded and converted into prioritized follow-up issues rather than omitted to improve the result.

The pass criteria cannot be weakened retroactively after seeing the session result.
