# Human Test Retirement Policy

Issue: #612

Repeated manual Product Reality verification is test debt when the observed fact is deterministic and measurable. The project must progressively remove Jeremy from routine laptop verification.

## Rule

Do not request a human laptop retest when an automated test, Windows automation lane, private local Product Reality scenario, or mature-reference differential test can answer the same question.

## Human review is reserved for

- actual Rocksmith 2014 gameplay feel when no automation/oracle exists;
- subjective tone and auditory preference;
- genuinely ambiguous fingering/playability judgment;
- final UX preference where instrumented usability evidence is insufficient;
- publication, licensing, copyright, or other owner-only authorization.

## Automation priority

When a human Product Reality session discovers a deterministic defect:

1. capture exact build/scenario/evidence;
2. reproduce the defect in a synthetic or private local automated scenario;
3. implement the fix;
4. add regression protection;
5. retire that fact from routine human verification.

A defect class should not require Jeremy to rediscover it twice.

## Product Reality reporting

Every Product Reality report should separate:

- automated deterministic PASS/FAIL;
- missing/stale evidence (`REVIEW_REQUIRED`);
- human-only acceptance debt.

The human-only list should be as short as possible. An empty list means no laptop session should be requested.
